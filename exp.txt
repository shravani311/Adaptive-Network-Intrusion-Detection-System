# 🟢 PHASE-WISE TECHNICAL REVISION

---

## ✅ PHASE 1 – Data Loading

• Dataset loaded using pandas
• 41 network traffic features
• Multi-class attacks converted to binary:

* 0 = Normal
* 1 = Intrusion
  • Dropped "difficulty" column

### Why drop difficulty?

* Not available in real-time systems
* Avoid data leakage

Output:

* X → 41 features
* y → binary label

---

## ✅ PHASE 2 – Preprocessing

### 🔹 Encoding (Categorical → Numeric)

Features like:

* protocol_type
* service
* flag

Converted using LabelEncoder.

Why?
→ ML models cannot process text directly.

---

### 🔹 Scaling

Used StandardScaler.

Why?
→ Prevent large numeric features from dominating smaller ones.

Important rule:
Train → fit_transform()
Test → transform()

Avoids data leakage.

---

## ✅ PHASE 3 – Handling Class Imbalance

Problem:

Normal samples > Attack samples
Model may bias toward normal.

Solution:

### 🔥 SMOTE (Synthetic Minority Oversampling Technique)

* Generates synthetic intrusion samples
* Balances dataset before training
* Applied ONLY on training data

Before SMOTE:
[67343 normal, 58630 attack]

After SMOTE:
[67343 normal, 67343 attack]

Why not on test?
→ Test must simulate real-world imbalance.

---

## ✅ PHASE 4 – Model Training

Model used: **XGBoost**

Why XGBoost?

✔ Boosting-based ensemble
✔ Corrects previous errors sequentially
✔ Better performance than Random Forest in many cases
✔ Handles complex attack patterns

---

### 🔧 Tuned Parameters

* n_estimators = 350
* max_depth = 8
* learning_rate = 0.05
* subsample = 0.8
* colsample_bytree = 0.8
* scale_pos_weight = 1.2

Why tuning?

→ Improve recall
→ Reduce false negatives
→ Maintain high precision

---

## ✅ PHASE 5 – Adaptive Threshold Logic

Instead of using:

predict()

We used:

predict_proba()

Example:

[0.25, 0.75]
75% probability of intrusion

Threshold = 0.25

If probability ≥ 0.25 → Intrusion
Else → Normal

Why lower threshold?

→ Increase recall
→ Reduce false negatives

IDS priority = catch attacks, even if some false alarms increase.
